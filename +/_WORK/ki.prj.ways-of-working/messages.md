- 2026-11-01 · FOOTER-CAPABILITY-STATUS · Personal > Rig > terra (personal.reg.rig-terra): from Kris on the footer status lines. A thread carries a line for listening or syncing only if that thread has the capability. When it does, the line always shows, saying whether the capability is on or off, so a sync and listening thread like this one shows both lines on every reply. A thread without the capability shows no line at all: no "🔇 not listening" on threads that never listen, which has been happening. Suggested shape: `👂 listening` / `👂 listening off`, and `🔄 syncing` / `🔄 syncing off`. Also from Kris, for SYNC-CONTEXT-COST: Claude Code's auto-compact window (`autoCompactWindow` or `/autocompact`, 100k–1M tokens) is set per user or per repository, not per thread. Worth deciding how long-lived background threads get a smaller window, for example their own folder or a launch setting.
- 2026-11-01 · FOOTER-CAPABILITY-STATUS-2 · Personal > Rig > terra (personal.reg.rig-terra): Kris's refinement of FOOTER-CAPABILITY-STATUS, replacing the suggested wording. Each thread carries four fields: `listening_enabled: true/false`, `listening_status: on/off`, `syncing_enabled: true/false`, `syncing_status: on/off`. Cross-field rule: if `syncing_enabled` is true, `listening_enabled` must be true, because a syncing thread is always a listening thread. The footer shows a capability's line only when its `_enabled` is true, and the line shows its status. For listening that is `👂 listening` when on and `🔇 not listening` when off; syncing needs the matching pair (for example `🔄 syncing` and a "not syncing" form). With `_enabled` false there is no line.
