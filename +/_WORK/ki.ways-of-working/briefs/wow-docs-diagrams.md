# wow-docs-diagrams - the diagram pipeline, vendored harness diagrams and the figure shortcode

Unit 2 of the website documentation plan. It changes generators and a shared layout, so it follows wow-docs-structure and runs before any page that embeds a diagram.

## Task

1. Declare `[skills.ki-diagrams]` in the website's `.ki.toml` as the harness documents in `skills/governance/ki-diagrams/SKILL.md` and `references/standards-diagrams.md`, read at `8897008f`. Create `docs/diagrams/diagrams.toml` with the manifest header comment and no tables yet, and `docs/diagrams/README.md` saying what lives there and how to regenerate.
2. Add `scripts/sync-diagrams.ts` and the `sync:diagrams` script, following `sync-ki-design.ts`: read a clean `../ki-agentic-harness` checkout (or `--from <path>`) at `--ref <sha>`, parse its `docs/diagrams/diagrams.toml`, and copy for every entry with `commit_html = true` the `<slug>.svg`, `<slug>.html` and `<slug>.receipt.json` into `apps/site/src/assets/diagrams/vendored/ki-agentic-harness/`, writing `apps/site/src/_data/vendoredDiagrams.json5` with the ref, the date and each slug's `type`, `question`, `last_checked` and file names. Run it at `8897008f`; expect twelve diagrams. The copied SVGs are Archify's `dual` form, which is what the harness commits; the figure places them on the same panel as site-owned `ki` forms.
3. Serve the interactive views: passthrough copy `apps/site/src/assets/diagrams/` to `/diagrams/` and `docs/diagrams/*.html` plus `*.svg` to `/diagrams/site/`, so no Eleventy transform touches an HTML viewer. Confirm the `explicit-index-links` and other transforms skip passthrough output.
4. Add a `figure` shortcode in `eleventy.config.ts`: `{% figure "skill-map", "caption" %}` inlines the SVG (vendored or site), wraps it in `<figure class="figure-diagram">` on a parchment panel with the caption, and appends an `Interactive` link opening the HTML in a new tab with `rel="noopener"`. Style it in the site's CSS for both charts. Add `scripts/build-diagrams.ts` and the `diagrams:build` script wrapping the harness `build-html.ts` and `export-svg.ts --form ki` for a site-owned slug, as `standards-diagrams.md` describes under Regeneration, so later units run one command.
5. Add `scripts/verify-diagrams.ts` and `verify:diagrams` in the `build` script after `verify:skill-names`: every `figure` slug in `src/docs/**/*.md` is in the site manifest or the vendored data; every site manifest entry has its `.json`, `.svg`, `.html` and receipt, and `build-html.ts --check` accepts it; every page embedding a vendored diagram declares a harness source whose `ref` equals the vendored ref. Add its test.
6. Prove the pipeline end to end with one site-owned diagram this unit owns and a page already needs: `command-groups` (architecture, the eighteen groups in `man/ki.1` at `v0.13.0`, traced to `man/ki.1`), drawn with `archify`, finalised with `diagrams:build`, committed with HTML and receipt, and embedded on `/docs/ki/command-groups/` in place of any Mermaid or list that stands for it. Leave the page's prose for the CLI unit.
7. Document the pipeline in `docs/guides/developer/diagrams.md`: vendoring, site-owned diagrams, the shortcode, the forms, the gate and the regeneration command.
