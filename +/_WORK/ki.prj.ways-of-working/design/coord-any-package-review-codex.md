## Own view - recorded before reflections

Formed before reflections. Recommend optional coordination for any existing work package, activated by an explicit owner-facing opener and bounded scope, never inferred from package existence, id, repository declaration or backlog size. Regular work remains regular; coordination is a session role. A finite backlog can use a temporary coordinating window without a new Project or permanent coordinator. State of play specialises this role across explicitly assigned packages, without changing sovereignty or acceptance authority. Confidence high.

Ranked eligibility: (a) explicit optional coordination for every valid package; (b) a narrow regular-work exception by owner instruction; (c) automatic coordination for every package. Prefer a, high confidence: it removes the category contradiction without imposing ceremony on conversational capture.

Ranked homes: (a) Capital/principal by default, with deliberate member-home exceptions recorded in Scope and discoverable by the parent; (b) unrestricted existing member-home freedom; (c) mandatory relocation of all packages. Prefer a, high confidence. Acquire already has a legitimate member home and explicit interim coordination authority; neither waits for general adoption. Home is not a claim about live session cwd.

Ranked pointer representations: (a) one non-authoritative home locator in the Capital's existing coverage/discovery surface, outside +/_WORK/, resolving repository identity plus work id; (b) a separately specified pointer-only type if existing surfaces cannot carry a locator; (c) two-file pseudo-package plus relay inbox. Prefer a, medium confidence: it preserves one physical package, state and authoritative queue without adding a second queue. Do not invent its filename or schema before inspecting reader ownership. A locator is not execution authority. If cross-repository sending must be forbidden, that becomes a separate durable relay design, not an incidental pointer detail.

Ranked tending: (a) parent State of play explicitly registers every package, routes messages to its authoritative home, and reviews unresolved ownership/unread or blocked messages at bootstrap/wake and periodic stewardship; (b) discover by repository scans alone; (c) appoint a permanent coordinator for every package. Prefer a, medium-high confidence. Coverage must include regular work and member homes, and tending must not silently launch execution, release holds or infer liveness from a binding. Recovery checks must flag missing/ambiguous homes and preserve messages rather than clear them. Direct delivery still needs committed receipt and retry discipline across hosts; no claim of exactly-once execution is justified.

Concise proposed decision: Any valid work package may host an explicitly opened coordinating session. Coordination does not alter work type, home, scope or authority and need not persist between bounded windows. Packages default to their territory's Capital; owner-selected member homes remain valid and are explicitly registered. Each work has one authoritative package, state and incoming queue; any Capital locator only directs senders to it. The parent State of play tends all packages it is assigned, including regular work, without automatically coordinating or executing them. Adopt the smallest discovery extension only after CLI and method gates are reconciled. This is advice, not enactment. Confidence high on principle, medium on locator mechanics.

## Risks and decision recommendations

Role inflation is the main policy risk: eligibility could be misread as mandatory or permanent coordination, a new Project, or a heartbeat for every regular package. Use explicit opening, scope and end condition, preserve conversational capture and apply responsiveness/delegation only during coordination.

False discovery is the main delivery risk: a method table may say regular/member packages are supported while readers omit them or reject their parent. Fix those exact readers before relying on a pointer; audit-style prose alone is insufficient. The current umbrella coverage restriction must be addressed without conflating coverage with an active session.

A shadow package or lightly specified relay creates duplicate state, forwarding loops and loss under interrupted multi-host commits. Prefer one locator and direct authorised queue delivery. If a sender cannot write the home under its actual authority, retain and route that limitation through existing SoP authority rather than grant cross-repository access by implication. If a relay is later chosen, specify and pilot it independently.

Tending can become accidental takeover. Use explicit, acknowledged assignment, preserve the actual worker/supervisor and per-package marks/holds, surface stale ownership, and never infer vacancy from silence or a missing binding. Do not add a scheduler or stewardship field through this design.

Authority and migration risk remain material: the general rule is not adopted, typed defaults are not live, and the isolated MOD011 candidate is not integrated. Keep Acquire's interim exception operating, make owner choices in the design loop, then deliver a receiver-owned pilot only under its own authority. This report neither authorises cross-territory writes nor proposes destructive or publication actions.

## COORD-ELIGIBILITY - Optional coordination for any valid package

**Context:** Current method forbids regular coordinators; the owner has approved Acquire's selected interim exception and requested design advice. A package and a repository capability declaration do not identify the active session role.

**Query:** Should every valid work package be eligible for an explicitly opened, scoped coordinating session, with conversational work remaining available and no automatic permanent coordinator?

**Options:**

a) (recommended, confidence high - removes the category contradiction while preserving owner choice) Make every valid package eligible through an explicit opener; retain work type, scope and authority, and state an end condition for bounded episodes.

b) Keep the existing prohibition with only specifically authorised regular-work exceptions.

c) Make every package automatically or permanently coordinating; this ranks last because package existence cannot establish an active coordinating role.

## PACKAGE-HOME - Principal default with deliberate member exceptions

**Context:** HNR prefers principal-homed packages; Acquire's owner explicitly selected its member home for independent repository working. Existing package standards already permit regular member homes.

**Query:** Should principal be the default while preserving owner-selected member homes declared in Scope and discoverable by the parent?

**Options:**

a) (recommended, confidence high - reconciles the two evidenced needs without moving work) Use principal as default, retain deliberate member exceptions including Acquire, and require parent discovery of the one real home.

b) Retain general member-home freedom without an explicit default or exception discipline.

c) Require all packages to live in the principal; no relocation authority is sought by this review.

## PACKAGE-POINTER - A locator with one authoritative queue

**Context:** A two-file pointer package violates the current closed contract; a full shadow package risks duplicate state. The owner asked for visibility and message discovery, but an exact representation is not yet adopted. Source evidence supports the single-home rule, not a particular new filename.

**Query:** Should a plain home reference in the Capital's existing governed coverage/discovery surface be the first representation to design and pilot, with direct authorised messages to the real queue?

**Options:**

a) (recommended, confidence medium - meets discovery with the fewest new semantics) Keep one explicit locator outside +/_WORK/, expressed through an existing governed surface; settle its exact representation against CLI readers before delivery, without inventing a second package or queue.

b) Specify a distinct pointer-only type if the existing surfaces cannot safely express repository identity and work id; require explicit reader and contract changes first.

c) Use the proposed two-file pointer package plus relay inbox; this retains its stage-one last ranking because it violates the present package contract. If a relay is essential, separately design it through the existing SoP queue with stable-origin receipts, retries and loop prevention, rather than adopting this pseudo-package.

**Context:** Acquire was missed by coverage-based tending; current readers also omit member homes and the umbrella regular form. A permanent coordinator is unnecessary for keeping a package discoverable and its messages accounted for. A new stewardship field remains undecided.

**Query:** Should the named parent State of play explicitly register and tend every assigned package, including regular/member-homed work, without inferring a coordinator session or execution authority?

c) Require a permanent coordinator for each package; this ranks last because tending and active coordination are separate needs.
