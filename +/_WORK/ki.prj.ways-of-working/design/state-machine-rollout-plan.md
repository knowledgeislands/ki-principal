## Disposition of the seven questions

### REST-PORTABLE - Settled

WORKING-EXIT explicitly makes stop "drain portable" on the common exit to At rest. WORK-CYCLE-SHAPE puts holding, waiting and moving in that one state; DIAGRAM-AGREED approves the latest common stop arc. TRANSITION-CONDITIONS and DRAIN-MEANS define the deletion-without-loss test. There is no approved waiting exemption. A short external wait may remain within active Working only when its actual holder/state is represented honestly; it cannot be called At rest before the full stop postcondition holds. WORKER-WAIT below prevents silently assigning such a wait to a nonexistent worker.

### WAIT-RESUME - Factual compatibility work

The approved diagram has At rest -resume, released-> Bootstrap; the machine source assigns resume to the supervisor role. WORK-CYCLE-SHAPE supplies the arc, not an automatic actor or scheduler. Current coordination, Picking work up, says a routed line waits without waking held work; Headless passes says a pass never opens or releases work and never runs for On hold or Finished. Package tending likewise creates no hold release. A reply can satisfy the waiting release condition without itself opening a session. Preserve that separation: an authorised opener/resume enters Bootstrap, then ready and the guarded entry follow. Check delivery/receipt and release in the package; do not build an automatic wake or treat the replying work as the supervisor. No new automatic-resume mechanism is required for this rollout, and the old unranked recommendation to have territory work advertise releases is not an adopted new sweeping duty.

### FINISH-FROM - Settled

WORK-CYCLE-SHAPE explicitly draws At rest -finish-> Finished; WORK-CYCLE-ENDS makes Finished terminal; WORKING-EXIT and DIAGRAM-AGREED fix the sole stop exit through End (work). A finish request during Working therefore concludes and stops before finish; a single turn may perform that sequence when every check passes. Current coordination's Finishing Project work lists close-out but does not encode this new source-state guard; update it rather than adding a direct finish edge. Nothing in the model permits self-acceptance, automatic finish or bypassing the strict run-close gate.

### WORK-REENTRY - Factual compatibility work

The agreed diagram is unchanged. Current coordination, Bootstrap and Picking work up, already requires re-bootstrap on request/model switch and re-anchoring after compaction, and describes With worker pick-up as "Recovery, not a planned restart". Re-reading a live package is a session procedure; it does not assert a persisted Bootstrap state or a resume from At rest. Preserve its recorded state and mark, reconcile actual runs and queued work, and continue only existing authority. Recovery on another host still requires the repository level check and truthful loss/unknown reporting. The source's transient BOOT-RECORD recommendation is not approval of a storage encoding; qualifying how a new opener differs from live recovery belongs to the implementation plan, without a new diagram arc.

### REST-NAMES - Settled

DIAGRAM-AGREED explicitly adopts At rest and the latest Archify shape, after WORK-CYCLE-SHAPE's earlier refinable names. Deliver the agreed arc names, Working, End (work) and At rest with holding/waiting/moving. Old commit subjects and banner text remain readable. Choosing conventional new commit wording that expresses these agreed transitions is compatibility drafting, not another request to approve the diagram's names.

### WORKER-WAIT - Genuinely unresolved owner choice

ROLES-ORCHESTRATOR's current read-back says With worker means a run holds the work; ROLES-EITHER changes who may enact a role, not whether the orchestrator has silently assumed it. Current coordination, States and moves, also keeps an orchestrator mid-turn and authorised work awaiting worker capacity With worker. The agreed diagram does not say which role holds those two cases. Neither retaining that old worker-side reading nor limiting the state to a live subagent can be inferred as a new approval. Isolate the case from active-run fixtures, supervisor handoffs and stop semantics.

**Context:** The role distinction is agreed. The current rule includes queued authorised work and an orchestrator mid-turn in With worker, while the new definition says a worker holds it. No running worker exists in either case; a queued unit must not be shown as running or as a decision for the supervisor merely because capacity is unavailable.

**Query:** Should With worker include these two cases as worker-side ownership, with an explicit queued/orchestrating description, or require an actual worker role holder before entering that state?

**Options:**

a) (recommended, confidence medium - retains the current capacity rule and the agreed diagram without inventing a new state) Retain With worker for these cases as worker-side ownership; state explicitly that this does not mean a run is in flight and show queued/orchestrating work accurately. Apply the same reading consistently to the source's narrower sentence and role/holder projections.

b) Require an actual worker role holder for With worker; qualify the entry/dispatch procedure and who holds authorised work before dispatch before enabling these cases. Do not invent a new state or redraw the agreed machine as part of this rollout.

### ROLE-WORDS - Settled

ROLES-ORCHESTRATOR, ROLES-EITHER and MACHINE-HOME require consistent supervisor, worker and orchestrator words. Restating source-table remnants such as "the session, as worker" is a required consistency correction in future owning contracts, not an optional new policy. Distinguish the role authorising an arc from the orchestrator executing/recording it and the actor triggering it. Keep preferred actor colours illustrative; they confer no authority. The only held semantic corner is WORKER-WAIT.
