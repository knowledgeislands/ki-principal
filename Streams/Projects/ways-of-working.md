## Outcome

Define how Kris works with agents - one master thread for project management, a small number of Project threads, detached background agents and the `ki` tools - in skills that transfer to any repository and runtime, rather than in personal preferences. The test: the thread and delegation rules live in `ki-delegation` and its sibling skills, a thread can roll up what has happened since a mark, and Kris can see the state of play across Projects and Initiatives at a glance.

- **Idea: notification strategy for delegated work.** One Knowledge Islands wide strategy for how the owner learns about delegated work from `ki agent` runs: `ki agent` derives an append-only events log per run (`progress`, `done`, `failed`, `blocked`, `needs-owner` and the run-level `all finished`), the thread channel is `ki agent wait --next` returning events at the coordinator's next turn, and a detached per-machine notifier (`ki agent notify`) pushes to remote channels behind one `deliver(event, destination)` adapter contract with receipts, quiet hours and duplicate suppression; Telegram is the preferred remote channel (a dedicated send-only bot, token in the macOS Keychain under the KI secret store, chezmoi carrying only the reference), Slack and a generic push service follow, platform-native notifications stay off by default, and the Observatory is a local Runs instrument over the run packets and receipts delivering over Server-Sent Events.
