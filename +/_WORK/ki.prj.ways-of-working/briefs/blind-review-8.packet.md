# Blind review 8 - masked packet

One open query for an independent view. Options are listed in no particular order and carry no recommendation. You may and should challenge earlier owner decisions and prior reasoning where the evidence warrants; an earlier decision is evidence, not a constraint.

## DISCUSSIONS

**Context:** In the Knowledge Islands work model, a coordinating thread collects the questions it needs its owner, Kris, to decide as "queries". Each open or parked query is kept in full in a work package file, `queries.md`, under `## Open` and `## Parked`, as Kris decided earlier under QUERIES-FILE and PARKED-HOME. Reports to Kris carry them under a `## Queries` section, each as a `### TAG - title` heading with **Context**, **Query** and **Options**. On 31 October 2026 Kris decided that, on request, queries are taken in an interactive pass one decision per turn (INTERACTIVE-QUERIES), shown with a counter such as "Query 3 of 7" (QUERY-TURNS), and that when the last query of the set is answered the coordinator takes a mark and then gives a Summary (QUERY-SET-MARK); the mark does not gather the decisions the set reached. On 31 October 2026 at 12:40 GMT Kris said: "these queries are really discussion points: you build up a number of discussion points, get to the end of them and end up with decisions. I am inclined to think these are in fact discussions", and asked for it to be decided urgently.

A reframing would rename the concept to "discussion point", the report section `## Queries` to `## Discussion`, and the pass counter to "Point 3 of 7"; close each set with one list of the decisions reached before the mark; and let a point close as "noted, no decision". Parking, the eight-point cap, confidence on the recommended option, plain English and blind review would stay. Anything that parses the section or the file must accept both names before anything writes the new one, or open points silently drop out of view. Readers include the harness rubrics and generated surfaces, the `ki` command-line tool (`src/core/agent/events.ts` and `thread.ts` read a report's `## Queries`) and the Observatory app (`packages/evidence/src/review.ts` and `focus.ts` read `queries.md` `## Open` and reports' `## Queries`). About 59 live work packages carry a `queries.md`. Renaming only the section moves no package: readers accept both section names, then writers switch, and past reports keep `## Queries`. Renaming the file as well adds a tolerance window in which every reader accepts both file names, a territory sweep renaming about 59 files repository by repository, updates to the package's closed file list and the package-creation rule, and closing the tolerance afterwards; the draft estimates roughly three times the work. Kris rarely opens the file directly. Leaving everything as it is was considered by the drafter and not offered.

**Query:** Should we rename queries to discussion points in what Kris reads only, or in the package files too?

**Options:**

- Do everything in the other option and also rename `queries.md` to `discussions.md` in every package, with a tolerance window in which every reader accepts both file names, then a territory sweep.
- Rename the concept, the report section, the pass wording and the end of the set, add the closing list of decisions and the "noted, no decision" ending, and keep `queries.md`; readers in `ki` and the Observatory accept both section names before the writers switch.
