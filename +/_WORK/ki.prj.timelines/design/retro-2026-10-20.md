# ki.timelines retro, 20 October 2026

## Working well

- Surveying first and asking Kris for improvements before any design run (TIMELINES-OPEN) meant the milestone-centred change, where spans never take busy time (TIMELINE-IMPROVEMENTS), shaped the design from the start rather than reworking it.
- Two independent design reviews, one on Claude and one on Codex, followed by blind Codex query reviews (tl-qreview, tl-qreview2), lifted nine design points to high confidence overnight without waking Kris (DESIGN-HIGH, DESIGN-REVIEWED, NAME-AND-PROVIDER).
- The idle 10-minute message checks overnight cost almost nothing and produced no false activity; when Kris came back at 01:49 BST the package already held the decided design and the handoff.

## Not working

- Launch friction cost turns: prepared prompts failed with "has already run" and had to be copied and relaunched; the Astra review started on the wrong model and had to be relaunched on Codex; the merge run then had to be relaunched to wait for it.
- Shell slips spent the five-call budget: `echo ====` aborted a command under zsh, and an unquoted path variable broke a commit that then had to be redone with explicit paths.
- Shared `main` gets in the way: a lint-staged backup failed while another session was committing, and the hold commit sits among other sessions' commits, so it cannot be pushed alone.
- Two Summaries carried wrong claims: one gave the KI-HARNESS-GOV-222 path under `Streams/Roadmap/`, and another suggested the 17 October autostash might be ours when it holds other sessions' files.
- After compaction two message watchers ran at once, giving duplicate wake-ups.

## Would change

- Check every path and ownership claim directly before it goes into a Summary, not from memory or a summary of one.
- At re-anchoring, list armed watchers and keep exactly one per work package.
- Give `ki agent launch` a per-role default for runtime, model and effort, so a review run lands on Codex at the strongest model without a relaunch.
