7.2 · Jobs

Every scheduled job and service Rig declares on either Mac, grouped by the territory and then the repository each one works in, as the built app does (src/app/jobs.ts). Kris asked for "a similar list view ... based on the scheduled jobs, by territory, and then by repository". It matters because a job that fails at 07:15 on one Mac is otherwise noticed only when its output is missed. Agora only shows: running, starting or stopping a job stays Rig's (KI-AGORA-WRK-004).

Refreshed 2026-11-06 · source: mock-ups from build/plan.py; not yet built

What it shows
  • Tallies (P2): All, Failed, Findings, OK, No run yet, Off, Services; Failed and Findings carry the gold edge while non-zero
  • Chips (P2): territory and plane from the context; one Filter menu for kind, Mac, profile and provider; words; Group by repository, Mac or none
  • Jobs (P3): name and Rig id, schedule in words, each Mac that runs it marked by how its last run there ended, last run, next run by its schedule, how it stands
  • Right tray (T1), a job chosen: its standing, purpose, the declaration (id, schedule, next, declared, profiles, provider, label, works in, program), each Mac's last runs as marks and the last one's line; Show runs, Open its file, Show on Home
  • Bottom pane (B1), after Show runs: every run kept on both Macs, newest first: finished, Mac, outcome, summary; and the declaration
  • Never shown: a job's environment, arguments or output

Region codes: B, the bottom pane (green); P, page content (brass); T, the tray and pop-outs (blue). Quote them as "7.2a P2".
